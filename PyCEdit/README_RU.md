# PyCEdit 1.15 — светлая версия

Редактор Python и C/PicoC для Casio fx-CG50. В комплекте оставлена только
светлая версия: готовый файл — [`PyCEdit.g3a`](PyCEdit.g3a). Имя в меню теперь
**PyCEdit**, внутренний идентификатор — `@PYCEDIT`. Два изображения иконки
побайтно сохранены без изменений относительно 1.14.

## Подсветка функций и строк

С учётом замечания о плохой читаемости прежних цветов в 1.15 на белом фоне
функции стали **синими**, а строки в кавычках — **красными**. Подсветка
предусмотрена и для Python (`.py`), и для C/PicoC (`.c`, `.h`). Ключевые
слова, числа и комментарии также имеют свои цвета; шрифт не менялся.

Идеализированный расчёт RGB565/sRGB показывает больший контраст новых
цветов с белым, чем у пурпурных функций и зелёных строк 1.14. Это не
измерение физического дисплея: воспринимаемую читаемость и различимость
цветов именно на LCD fx-CG50 нужно проверить отдельно.

### Как проверить на калькуляторе

1. Сохрани свои `.py`, `.c` и старый аддин на компьютере. Если на калькуляторе
   есть предыдущий `PyCLite.g3a`, удали **только его**, иначе может остаться
   вторая версия. Скопируй новый `PyCEdit.g3a`; если одноимённый старый файл
   уже есть, замени его после резервного копирования. Рабочие `.py` и `.c`
   удалять не нужно. При желании скопируй `Examples/PYTEST.py` и `Examples/CTEST.c`.
2. Убедись, что в меню написано **PyCEdit**, и открой пример через FILES →
   EDIT. На верхней строке будет `[PY]` для Python или `[C]` для C. Цвета
   видны в открытом файле, а не в списке. `[TXT]` означает, что расширение
   не распознано.
3. Проверь синий `print` и красную строку в `.py`, затем синий `printf` и
   красную строку в `.c`. Например, можно ввести `print("Hello World")` в
   Python или `printf("Hello World");` в C. Если что-то всё ещё плохо видно,
   пришли фото с верхней строкой, чтобы можно было подстроить цвета.

В `Examples/` есть также два средних тестовых файла: `COLORPY.py` и
`COLORC.c`. Их можно просто открыть и пролистать; запускать для проверки
цветов не обязательно.

Лексическая подсветка не является полным синтаксическим анализатором:
например, Python f-строка окрашивается целиком, её выражения не разбираются
отдельно. Тройные кавычки Python и многострочные комментарии C учитываются
при прокрутке в программных тестах.

## Список Python-модулей для вставки

В открытом файле нажми **F3 SYM → F5 PYMOD**. На трёх страницах — 18 шаблонов,
например `import math`, `import random`, `import gint` и `import kandinsky`.

- **↑/↓** — выбрать строку; **←/→** — страница назад/вперёд; **F5** —
  следующая страница, **SHIFT+F5** — предыдущая.
- **EXE** вставляет выделенную строку `import имя` и перевод строки в текущую
  позицию курсора. Цифры **1–8** вставляют соответствующий пункт страницы.
  **F6/EXIT** закрывает меню без вставки. F1–F4 открывают прежние разделы.
- Пункты без метки — обычные примеры для Casio Python (`math`, `random`,
  `casioplot`; доступность последнего зависит от прошивки).
- **`[PE]`** — ориентир на PythonExtra/MicroPython; такие модули могут
  отсутствовать во встроенном Python или в другой сборке PythonExtra.
- **`[FILE]`** — требуется отдельный файл модуля: `turtle.py` или
  `matplotl.py`. В этот комплект эти файлы не входят. Некоторые версии
  [PythonExtra](https://git.planet-casio.com/Lephenixnoir/PythonExtra/releases)
  распространяют их отдельно; путь установки зависит от интерпретатора.

Список **только вставляет текст** и не устанавливает модули, не добавляет
возможности в PythonExtra и не гарантирует, что все функции модуля есть в
конкретной версии. Список составлен по исходникам PythonExtra beta 0.4 и
документации; точная конфигурация пользовательской готовой сборки неизвестна.
В поддерживающем это REPL можно посмотреть встроенные модули командой
`help('modules')`. Подробности — `tools/python_modules_reference.txt`.

## C/PicoC: заголовки и перелистывание

В открытом файле: **F3 SYM → F4 LIBS**. Управление страницами и вставкой такое
же, как в PYMOD. Сохранены 62 заголовка на восьми страницах: 43 имён,
зарегистрированных в PicoC проверенной версии Utilities, и 19 заголовков
нативного SDK с пометкой `[SDK]`. `[SDK]` **не** означает, что этот include
доступен в PicoC. Например, `<stdio.h>` в проверенном PicoC не зарегистрирован
как `#include`. Остальные старые вкладки SYMS, C/PICO и PYEXT сохранены.

## Сборка

Нужны `sh3eb-elf-gcc`, libfxcg/PrizmSDK с `toolchain/prizm_rules`, mkg3a и
Python 3. В WSL/Linux из этой папки:

```sh
export FXCGSDK="$HOME/PrizmSDK"
export PATH="$FXCGSDK/bin:$PATH"
make                  # PyCEdit.g3a; только светлая версия
```

Для проверенной сборки использованы GCC 14.1.0 и libfxcg v0.6 без LTO.
Makefile встраивает BMP в RGB565 и пересчитывает суммы; Pillow для обычной
сборки не нужен. `fxgxa -d PyCEdit.g3a` проверяет заголовок. О проверках и
их ограничениях см. `ПРОВЕРКИ_1.15_RU.md` и `tools/README_RU.md`.
Компьютерные снимки в `Computer_screens/` — не фото настоящего калькулятора.
